# AGENTS.md

Guidance for AI coding agents working in doctools-docs, the documentation site for Isik's Tech's documentation tools (<https://doctools.isiks.tech>). The tools themselves live in their own repositories; this repository holds all of their human-facing documentation.

## What lives where

- `mkdocs.yml` — the Zensical configuration. Its look (Material theme, amber palette, fonts, features, admonition icons, `extra.css`, the `isikstech` social card layout) matches the Isik's Tech PCB docs site, `docs-zensical`; keep the two in step.
- `docs/pinconnect/` — PinConnect's docs. `docs/3dstep/` — 3DStep's. `docs/md-iframe/` — md-iframe's. `docs/guides/` — topics shared by every tool (publishing, light and dark mode), written once and linked from each tool's pages. `docs/migration.md` — the old names (`pinout-gen`, `pinout-embed`) and what replaced them.
- `docs/pinouts/<name>/<name>.toml` — the sources of the PinConnect live examples. CI renders each with `pinconnect "$toml" -i`, and pages embed the result with `{ type=iframe }`. `docs/pinouts/isikstech.toml` is a theme, not a board: it sits outside the board folders so the loop never renders it. Generated `*.pinout.html` files are git-ignored.
- `docs/3d/<name>/*.toml` with their `.glb` models — the sources of the 3DStep live examples. CI renders every TOML with `3dstep "$toml"`; a folder may hold several projects over one model (`pican2.toml` in the site theme, `pican2-default.toml` in the bundled one). `docs/3d/isikstech.toml` is the site's 3DStep theme, kept outside the folders like the PinConnect one. Generated `*.3dstep.html` files are git-ignored.
- `docs/assets/pinconnect/` and `docs/assets/3dstep/` — doc images, all generated by `tools/` (see `tools/README.md`), except `3dstep-demo.gif`, which is the 3DStep repository's README animation.
- `.github/workflows/ci.yml` — installs `zensical`, `pinconnect`, `3dstep` and `md-iframe` from their repositories' `master`, renders the live examples, builds and deploys to GitHub Pages. `docs/CNAME` holds the custom domain.

## Keeping the docs in step with the tools

The tools' behavior is documented here, not in their repositories, so a change to a tool usually needs a change here too:

- The PinConnect references (`docs/pinconnect/reference/board-toml.md`, `connector-types.md`, `themes.md`) describe the same three schemas as PinConnect's `src/pinconnect/config.py`. Change them together.
- The 3DStep references describe 3DStep's code the same way: `docs/3dstep/reference/project-toml.md` and `themes.md` its `src/threedstep/config.py` (keys, defaults, checks, tokens, behaviors), `page.md` its `src/threedstep/viewer/viewer.js` (controls, keys, URL parameters, messages), and `docs/3dstep/designer.md` its designer (tools, shortcuts, dialogs). `docs/3dstep/command-line.md` follows `3dstep --help` and the messages of `cli.py`.
- `docs/md-iframe/auto-height.md` is the contract other tools implement: the `mdIframeHeight` message, with `pinconnectHeight` accepted. It must match md-iframe's listener script.
- `docs/guides/light-dark.md` describes the generated page's theme-sync contract (`?theme=`, the embedding page's scheme, `{pinconnectTheme}`). It must match PinConnect's renderer, and 3DStep's, which copies it verbatim.
- `docs/migration.md` lists every compatibility promise. Those promises are permanent; never document one as removed.
- After a change that affects how something looks, rerun the matching generator in `tools/`, pixel-diff the result, and commit only images that really changed.

## Conventions

- **US English, one line per paragraph.** Do not hard-wrap prose. Use the spellings that match the TOML keys (`colors`, `behavior`, `gray`).
- **Alt text on every image**, and a title (alt text) on every embed: md-iframe turns it into the iframe's accessible name.
- **Prefer a live embed** to a static image wherever an embed can work. Static images stay only where a live page cannot: screenshots of the designer, and pictures of several states side by side.
- **Use the new names** (`pinconnect`, `md-iframe`, `{ type=iframe }`, the install lines without `#subdirectory`). The old ones appear only on the migration page and in brief notes that they still work.
- **Promise nothing a tool does not do yet.** Describe today's behavior and its workaround (a STEP file too big for the designer: split it or convert it on a machine), not a planned feature.
- **The build must stay clean.** `zensical build --clean` reports broken links and anchors; fix every one.
- Plans, known-bug lists and tests are local only and git-ignored (`PLAN-*.md`, `KNOWN-BUGS*.md`, `tests/`, `test_*.py`). Never commit them.

## Verifying changes

Install the tools into `venv/` (git-ignored), render the live examples, and serve the site; `README.md` has the commands. Check pages in a browser: embeds load and size themselves, and light/dark follows the site's toggle.
