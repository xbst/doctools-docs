# Publish on a docs site

The tools on this site produce HTML pages, and md-iframe embeds them in an MkDocs or Zensical site. Rather than committing generated pages, it is usually better to generate them during the build: keep only the sources in the repository, and let CI produce the HTML on every deploy. This site is built exactly this way.

The example below uses PinConnect and GitHub Pages; the pattern is the same for any tool and any host.

## Lay out the sources

Keep one folder per board, holding its TOML and its image. CI writes `<board>.pinout.html` beside each TOML, exactly where the embed tag on your page points:

```
docs/
├── boards.md
└── pinouts/
    └── board/
        ├── board.toml            ← committed
        ├── board.png             ← committed
        └── board.pinout.html     ← generated by CI, not committed
```

The page embeds the generated file:

```markdown
![Board pinout](pinouts/board/board.pinout.html){ type=iframe }
```

Ignore the generated files so they never get committed by accident:

```gitignore
docs/pinouts/**/*.pinout.html
```

## Enable md-iframe

In `mkdocs.yml`, beside `attr_list`:

```yaml
markdown_extensions:
  - attr_list
  - md_iframe
```

## Generate in the workflow

Add these steps to your workflow before `mkdocs gh-deploy` or `zensical build`:

```yaml
      - run: pip install "git+https://github.com/xbst/PinConnect.git@master"
      - run: pip install "git+https://github.com/xbst/md-iframe.git@master"
      - name: Generate interactive pinouts
        run: |
          shopt -s nullglob
          for toml in docs/pinouts/*/*.toml; do
            echo "pinconnect $toml"
            pinconnect "$toml" -i
          done
```

`-i` embeds the board image into the HTML, so the built site does not depend on the image path resolving. `shopt -s nullglob` keeps the loop quiet when a folder has no TOML yet.

!!! tip "Install from `master` rather than pinning a release"
    Each deploy then regenerates your pages with the current version of the tools, so fixes and new features in the generated page, such as tooltip behavior, theming, accessibility and the mobile layout, reach your published site automatically.

## A complete workflow

This is a whole GitHub Pages workflow for a Zensical site, the one this site uses. Save it as `.github/workflows/ci.yml`, and set the repository's Pages source to **GitHub Actions**:

```yaml
name: ci
on:
  push:
    branches:
      - master
      - main
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/configure-pages@v6
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v6
        with:
          python-version: 3.x
      - run: pip install zensical
      - run: pip install "git+https://github.com/xbst/PinConnect.git@master"
      - run: pip install "git+https://github.com/xbst/md-iframe.git@master"
      - name: Generate interactive pinouts
        run: |
          shopt -s nullglob
          for toml in docs/pinouts/*/*.toml; do
            echo "pinconnect $toml"
            pinconnect "$toml" -i
          done
      - run: zensical build --clean
      - uses: actions/upload-pages-artifact@v5
        with:
          path: site
      - uses: actions/deploy-pages@v5
        id: deployment
```

For MkDocs, install `mkdocs-material` instead of `zensical`, and run `mkdocs build` in place of `zensical build --clean`.

## Build locally

Run the same steps on your machine to preview the site. In a virtual environment with the same packages installed:

**PowerShell**

```powershell
Get-ChildItem docs/pinouts/*/*.toml | ForEach-Object { pinconnect $_.FullName -i }
zensical serve
```

**Linux / macOS**

```bash
for toml in docs/pinouts/*/*.toml; do pinconnect "$toml" -i; done
zensical serve
```

Rerun the loop after editing a TOML: the dev server rebuilds the page, but not the pinout.

## A shared theme

A site-wide pinout theme, matching your site's colors and fonts, can live once beside the board folders. Each board points at it with `theme_dir`:

```toml
[board]
title = "My board"
image = "board.png"
width = 1920
height = 1080
theme = "mysite"
theme_dir = ".."
```

with the theme in `docs/pinouts/mysite.toml`. The loop above only renders `docs/pinouts/*/*.toml`, so the theme itself is never rendered as a board. This site's [OwlFC-Mini example](../pinconnect/examples/board.md) uses one; see [Theming concepts](theming.md) and the [PinConnect themes reference](../pinconnect/reference/themes.md).
