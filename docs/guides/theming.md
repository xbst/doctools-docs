# Theming concepts

The tools on this site generate a page from data you provide, and a **theme** decides how that page looks around the data. PinConnect works this way, and the tools to come will use a similar system, so the concepts here carry over.

## Data and theme are separate

The data describes *what* is shown: for PinConnect, the board, its connectors, and each pin's name and wire color. The theme describes *how* the page around it looks: colors, fonts, and layout behaviors. The same board renders in any theme, and a reader sees the same wire colors in every one.

Keeping them apart means one theme can serve a whole site: every pinout on it matches, and a change to the theme restyles all of them on the next build.

## What a theme holds

A theme is a TOML file with up to four parts:

- **`[colors.light]` and `[colors.dark]`**: two palettes of named color tokens, one per scheme. The page picks one as [Light and dark mode](light-dark.md) describes.
- **`[font]`**: the text font and where it comes from: Google Fonts, a font file embedded into the page, or a system font that needs no download.
- **`[behavior]`**: layout choices, such as whether the side list starts open, and the screen width below which it stacks under the main content.
- **`[extra_css]`**: raw CSS for anything the tokens cannot express.

A theme only states what differs. Every token it leaves out falls back to the built-in default, so a useful theme can be a handful of lines.

## How a theme is chosen

1. A theme given on the command line (`pinconnect board.toml --theme ocean`) wins.
2. Otherwise the theme the data names (`theme = "ocean"` in `[board]`).
3. Otherwise the `default` theme.

The name is looked up in a folder beside the data first (`theme_dir`, `./themes` by default), then among the themes bundled with the tool. A theme of your own with a bundled name overrides the bundled one for that board.

## Matching your site

To make generated pages look like part of your docs site:

- Set the page background to `transparent` in both palettes, so your site's own background shows through the iframe.
- Use your site's accent color for highlights and your site's fonts.
- Keep the theme once beside your board folders and point every board at it with `theme_dir`, as [Publish on a docs site](publishing.md#a-shared-theme) shows.

This site does exactly that for its [OwlFC-Mini example](../pinconnect/examples/board.md): its theme is transparent, amber like the site's header, and set in Roboto to match. The examples that use the `default` theme show the other approach, a page with its own background.
